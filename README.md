# Система управления заявками жильцов

Django-приложение для просмотра жильцов, исполнителей и заявок ЖКХ.
В ПР9 веб-страницы переведены на Django ORM. В ПР10 добавлены администрирование,
коды статусов заявок и проверка доступности исполнителя на дату. Предыдущий SQL-вариант описан
в [README ПР7](README_PR7.md), консольный вариант — в [README ПР1–ПР6](README_PR1_PR6.md).

## Запуск

```powershell
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py import_pr7
python manage.py runserver
```

Откройте http://127.0.0.1:8000/. При переходе с ПР7 сохраните резервную копию
`data/tenant_requests.sqlite` и существующей `db.sqlite3`. Команда `import_pr7`
открывает базу ПР7 в режиме чтения и одной транзакцией переносит жильцов,
исполнителей и заявки в `db.sqlite3` с исходными ID и внешними ключами.
При необходимости путь передаётся через `--source`. Повтор с теми же данными
безопасен. При конфликте с изменёнными записями в Django весь перенос отменяется.
После начала работы с Django импорт повторно запускать не требуется.
Если файла ПР7 нет, его можно восстановить из JSON командой `python -m db.import_json`.

## Модели и сценарии

- `Tenant`: имя, положительный номер квартиры, необязательный телефон.
- `Executor`: имя, специализация, учётный признак занятости.
- `Request`: описание проблемы, дата, категория, статус и два внешних ключа.
  Жилец обязателен, исполнитель может отсутствовать. Обратная связь называется
  `requests`. Удаление связанного родителя блокируется через `PROTECT`.
- `/tenants/` и `/executors/`: списки и карточки. Поиск жильца работает по имени
  или номеру квартиры. Свободным считается исполнитель без признака занятости
  и без заявок в статусах «Новая» и «В работе». При выбранной дате
  учитываются заявки этой даты. Без даты проверяются все активные заявки.
- `/requests/`: поиск по проблеме и имени жильца, фильтры по дате, категории,
  статусу и связанным записям. Сортировка по дате или жильцу и пагинация по 10 строк.
  Ошибочное поле помечается в форме, корректные фильтры продолжают действовать.
- `/requests/1/` и `/requests/statistics/`: карточка заявки и статистика
  по заявкам, категориям и исполнителям. Исполнители без заявок учитываются.

Список заявок использует `values()` и `annotate(F(...))` для получения словарей
с данными связей. Карточка использует `select_related()`. Счётчики и группировка
выполняются через `Count`, `Min`, `Max`, `aggregate()` и `annotate()`.

## Администрирование ПР10

```powershell
python manage.py createsuperuser
```

Откройте http://127.0.0.1:8000/admin/ и войдите в Django. Модель жильца
принадлежит предметной области, а вход использует учётные записи Django.
В админке доступны русские названия, поиск, фильтры и сортировка. В карточках
жильца и исполнителя заявки можно просматривать и редактировать через inline
при наличии разрешений. Признак занятости редактируется прямо в списке
исполнителей. Стандартные разрешения Django определяют доступ к операциям,
а `PROTECT` сохраняет связанные записи при удалении родителя.

При обновлении с ПР9 сделайте копию `db.sqlite3` и выполните `python manage.py migrate`.
Миграция заявок переводит «Новая», «В работе», «Выполнена», «Отменена» в
`new`, `in_progress`, `completed`, `cancelled`. Русские названия видны в интерфейсе,
старые ссылки с русским статусом продолжают фильтровать. Методы
`Request.objects.active()`, `cancelled()`, `completed()` и `for_date(day)`
можно сочетать с обычными фильтрами ORM. Активны `new` и `in_progress`.
Завершённые и отменённые заявки не препятствуют доступности исполнителя.

Миграция исполнителей заполняет уникальный slug существующих записей
значением `executor-<ID>`. Канонические ссылки формируются
`get_absolute_url()`, например `/executors/profile/executor-1/`.
Старые ссылки по числовому ID продолжают открывать карточку.

## Проверка

```powershell
python manage.py check
python manage.py showmigrations
python manage.py makemigrations --check --dry-run
python manage.py test
python -m pytest -v
python -m flake8 . --extend-exclude=venv,migrations
```

Для анализа SQL на локальном сервере задайте `$env:DJANGO_DEBUG_TOOLBAR = '1'`
перед `runserver`. В панели SQL списка заявок видны подсчёт и выборка страницы.
Карточка получает заявку с жильцом и исполнителем одним SELECT.
